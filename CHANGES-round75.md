# Round 75 — Modal recovery and working compact filters

- Portaled the QR preview and edit Bootstrap modals to `document.body`, so fixed dialogs no longer inherit clipped or transformed workspace ancestors. On preview close, the poster node returns to its original print-source position (with a safe fallback), preserving print/download markup.
- Portaled the public Support confirmation dialog out of its page wrappers. The dialog now locks mobile and desktop page scrolling, traps focus, and restores the previous focus, scroll position, and inline body/root styles on cancel, backdrop click, Escape, and confirmation submit.
- Made compact filter menus dismiss on outside click and Escape, exposed their expanded state to assistive technology, and fixed active date-chip labels. Search and all field changes refresh chips; existing GET submission, query filters, and server-side sorting remain unchanged.
- Corrected overflow and stacking for filter-bearing cards/registers so opaque popovers render above surrounding table content rather than being clipped by rounded cards.
- Fixed the shared light-mode theme tokens: card, raised-card, ink, and muted values were missing, and the settings preview removed the card tokens in light mode. Workspace cards, filter popovers, and form surfaces now resolve to opaque, readable values in light mode as well as the existing dark palette.
- Added regression coverage for QR/support modal hooks, combined case-document search/status/completion/date filters, agency document-request filters and account scoping, and Feedback triage filters. Existing page-specific layouts, data access, permissions, routes, and workflows were retained.
- Validation: 64 focused feature tests passed (452 assertions) in the implementation run; an independent targeted run passed 52 tests. Blade cache compiled and cleared; `node --check public/js/filter-bar.js`, PHP lint, PostCSS parse of `workspace.css`, and `git diff --check` passed.
- Browser verification on the available local Support page confirmed the dialog is centered above the footer, body scrolling is locked while open, and closing restores the prior scroll position and focus. Authenticated staff-page visual verification was unavailable; QR modal behavior is covered by rendered integration-hook tests, not a live browser interaction.
